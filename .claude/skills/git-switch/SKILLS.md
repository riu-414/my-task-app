# Git Switch スキル — ブランチの作成と切り替え

新しいブランチを作って作業を始めるときの手順と、ブランチ名の付け方をまとめたメモです。

---

## 1. 基本コマンド

### 現在のブランチを確認する

```bash
git branch
```

- 今いるブランチには `*` が付きます。
- リモートも含めて確認したいときは `git branch -a`。

### 新しいブランチを作って切り替える（よく使う！）

```bash
git switch -c <新しいブランチ名>
```

- `-c` は **create**（作成）の意味。
- ブランチを作ると同時にそのブランチへ移動します。
- 例: `git switch -c feature/login-form`

> 💡 古い書き方では `git checkout -b <ブランチ名>` を使っていましたが、現在は `git switch` の方が推奨されています（`checkout` は機能が多すぎて分かりにくいため、`switch` と `restore` に分割されました）。

### 既存のブランチに切り替える

```bash
git switch <ブランチ名>
```

- 例: `git switch main`

### 直前のブランチに戻る

```bash
git switch -
```

- ハイフン1つで「ひとつ前にいたブランチ」に戻れます。

### リモートにあるブランチを取ってきて切り替える

```bash
git fetch origin
git switch <リモートのブランチ名>
```

- リモートのブランチ名と同じローカルブランチが自動で作られます。

### ブランチの削除

```bash
git branch -d <ブランチ名>     # マージ済みなら削除
git branch -D <ブランチ名>     # 強制削除（未マージでも削除）
```

---

## 2. ブランチを切る前のチェックリスト

1. `git status` で未コミットの変更がないか確認する。
2. `git switch main` で main ブランチに移動する。
3. `git pull origin main` で最新の状態に更新する。
4. `git switch -c <新しいブランチ名>` でブランチを作る。

---

## 3. Git ブランチタイプ一覧

ブランチ名は `<タイプ>/<内容>` の形で付けるとチームでも自分でも分かりやすくなります。

| 接頭辞 | 絵文字 | 用途 | 命名例 |
| :--- | :---: | :--- | :--- |
| `feature/` | ✨ | 新しい機能の開発・追加 | `feature/user-profile` |
| `fix/` | 🐛 | バグの修正 | `fix/login-error` |
| `hotfix/` | 🔥 | 本番環境で発生した緊急性の高いバグ修正 | `hotfix/payment-crash` |
| `release/` | 🚀 | リリースに向けた準備作業（バージョンアップなど） | `release/v1.2.0` |
| `docs/` | 📝 | ドキュメントの作成・修正 | `docs/update-readme` |
| `refactor/` | ♻️ | 既存コードの改善（リファクタリング） | `refactor/auth-module` |
| `chore/` | 🔧 | ビルドツールや設定など、開発環境の変更 | `chore/update-eslint` |
| `test/` | ✅ | テストコードの追加・修正 | `test/add-task-spec` |

---

## 4. よくあるミスと対処法

- **間違ったブランチで作業を始めてしまった**
  → コミット前なら `git stash` で一旦退避 → 正しいブランチに `git switch` → `git stash pop` で戻す。
- **ブランチ名をタイプミスした**
  → `git branch -m <旧名> <新名>` でリネームできます。
- **`switch` コマンドが使えない**
  → Git のバージョンが古い可能性。`git --version` を確認し、2.23 以上にアップデートしてください。
