# Git Push スキル — ステージング・コミット・プッシュ

書いたコードをリモートリポジトリ（GitHub など）に反映するまでの流れと、コミットメッセージの書き方をまとめたメモです。

---

## 1. 基本の流れ（3ステップ）

### ステップ1: 変更をステージングする（`git add`）

```bash
git status              # まずは何が変わったか確認
git add <ファイル名>     # 特定のファイルをステージング
git add .               # カレントディレクトリ以下の変更をすべてステージング
```

- 「ステージング」とは、コミットに含める変更を選ぶ作業のことです。
- 例: `git add src/App.tsx`
- 一括で追加したいときは `git add .` が便利ですが、意図しないファイル（`.env` など）が混ざらないよう `git status` で必ず確認しましょう。

### ステップ2: コミットする（`git commit`）

```bash
git commit -m "<接頭辞>: <変更内容を簡潔に>"
```

- 例: `git commit -m "feat: ログイン画面を追加"`
- `-m` はメッセージを直接書くオプション。省略するとエディタが開きます。
- メッセージは「何を」「なぜ」変えたかが分かるように書きます。

### ステップ3: リモートにプッシュする（`git push`）

```bash
git push origin <ブランチ名>
```

- 例: `git push origin feature/login-form`
- 初回プッシュ時は `-u`（upstream）を付けると、次回から `git push` だけで OK になります。
  ```bash
  git push -u origin feature/login-form
  ```

---

## 2. プッシュ前のチェックリスト

1. `git status` で意図した変更だけがステージングされているか。
2. `git diff --staged` でステージング内容を確認する。
3. `git log --oneline -5` で直近のコミット履歴を確認する。
4. `git push` を実行する。

---

## 3. Git コミットメッセージ接頭辞一覧

コミットメッセージの先頭に「種類」を付けると、後から履歴を追いやすくなります（Conventional Commits 風）。

| 接頭辞 | 絵文字 | 用途 | コミット例 |
| :--- | :---: | :--- | :--- |
| `feat` | ✨ | 新機能の追加 | `feat: タスク追加機能を実装` |
| `fix` | 🐛 | バグの修正 | `fix: 削除ボタンが反応しない問題を修正` |
| `docs` | 📝 | ドキュメントのみの変更・追加 | `docs: READMEに環境変数の説明を追加` |
| `style` | 💅 | コードの動作に影響しない変更（フォーマット、インデント、セミコロンなど） | `style: prettierでコード整形` |
| `refactor` | ♻️ | バグ修正や機能追加ではないコードの改善（リファクタリング） | `refactor: タスク一覧コンポーネントを分割` |
| `perf` | ⚡️ | パフォーマンスを向上させる変更 | `perf: 一覧描画をメモ化して高速化` |
| `test` | ✅ | テストコードの追加・修正 | `test: ログインフォームのテストを追加` |
| `chore` | 🔧 | ビルドツールや設定ファイルなど、開発環境に関する変更（雑用） | `chore: .gitignoreを更新` |
| `build` | 🏗️ | ビルドシステムや外部依存関係の変更（npm, webpackなど） | `build: viteを最新版に更新` |
| `ci` | 🤖 | CI/CDに関する設定ファイルの変更 | `ci: GitHub Actionsのワークフローを追加` |
| `revert` | ⏪ | 以前のコミットを取り消す変更 | `revert: feat: タスク追加機能を実装 を取り消し` |

### 書き方のコツ

- **件名は50文字以内**を目安に。
- **動詞は現在形・命令形**で書く（「追加した」ではなく「追加」）。
- 詳細を書きたいときは1行空けて本文を書きます。
  ```
  feat: タスク並び替え機能を追加

  ドラッグ&ドロップで並び替えできるよう react-dnd を導入。
  並び順は Supabase の order カラムに保存する。
  ```

## 4. よく使う応用コマンド

### 直前のコミットメッセージを修正したい

```bash
git commit --amend -m "新しいメッセージ"
```

> ⚠️ すでにプッシュ済みのコミットを `--amend` するとリモートと履歴がズレます。共有ブランチでは使わないように。

### ステージングを取り消したい

```bash
git restore --staged <ファイル名>
```

### ファイルの変更そのものを取り消したい

```bash
git restore <ファイル名>
```

### プッシュを取り消したい（自分専用ブランチのみ）

```bash
git reset --hard HEAD~1
git push --force-with-lease origin <ブランチ名>
```

> ⚠️ `--force` 系は他の人の作業を壊す危険があります。共有ブランチでは絶対に使わないこと。

---

## 5. 困ったときに確認すること

- `git status`: 今の状態を確認する万能コマンド。困ったらまずこれ。
- `git log --oneline --graph --all`: 履歴を視覚的に確認できる。
- `git remote -v`: プッシュ先のリモート URL を確認できる。
